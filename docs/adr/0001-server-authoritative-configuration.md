# 0001 — 配置以服务器确认为准，浏览器保留草稿

用服务器配置版本校验取代浏览器时间戳的最后写入者胜出策略。GET /api/config 返回 ETag，PUT 必须带 If-Match；SQLite 写事务原子比较和保存，避免两个标签页或进程互相覆盖。浏览器串行发送修改，只在收到成功确认和新版本后显示已保存，失败保留草稿。

## 取舍

不采用客户端时间排序，因为新建空缓存的本机时间也会比真实配置新；不自动把冲突草稿强制重发，因为它可能删除其他设备新增的模型。代价是冲突需要显式处理，旧直接 PUT 客户端需先 GET 版本（缺少版本返回 428，过期版本返回 412）。旧配置迁移仅允许写入尚无配置记录的服务器。

## 恢复边界

每个标签页用独立 sessionStorage 保存待同步草稿，共享 localStorage 作为兼容缓存；旧格式或无法解析的共享缓存在第一次替换前备份到 comicpedia_api_config_legacy_backup。这不是完整备份系统，也不是密钥隔离方案；窗口关闭后的完整恢复、默认无密钥导入导出和服务端凭据 DTO 仍待后续重构。
