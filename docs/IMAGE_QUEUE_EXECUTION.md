# 图片队列并发与异步回写

2026-09-20。此批承接创作配置中的图片并发设置，实现单作品的有界执行，不是多进程分布式任务系统。

## 执行契约

- 同一个作品使用 `presetSnapshot.imageConcurrency`，兼容历史 `imageQueue.imageConcurrency`。有效范围 1–4；服务端将超界整数约束到此范围，非法值和无配置的历史任务按 1 执行。
- 每个槽位包含图片请求、保存、挂接与可选的轻量检查。任意槽位完成后再补入下一个待处理任务；不是每轮等整批完成。
- 校准尚未通过时只派发一张样片。成功后其他任务进入校准等待；样片失败或远程未返回时，本次运行不会自动放行余下任务。
- 暂停操作暂停尚未派发的任务；已经派发的请求允许完成并持久化，恢复后处理余下任务。这里的暂停不是上游请求撤销，也不保证停止计费。
- ComfyUI 等待超时仍保留远程 prompt ID。发现仍在执行的远程请求后停止派发新任务，并等待本次其他已派发槽位结束；下次恢复先等待持久化的 prompt，不重复提交。
- 同一次队列运行不重复执行同一 job ID。TaskRuntime 保持每个作品单个队列运行；本批不新增跨进程锁。
- 显式重新入队包含正在 generating/persisting/light_check 的分镜时，整批拒绝，HTTP 返回 409，不把活动 job 覆盖为 queued。添加其他空闲分镜仍受原队列支持。
- 单个请求失败不阻止其他槽位完成；首次失败面板显示 failed，已有成功图片的重绘失败保留原图。任务汇总据实际 jobs 显示暂停/失败，而非永远显示面板生成中。

## 防止异步结果覆盖

`imageRunner.ts` 将单分镜执行与调度分离。队列汇总在 await 之后读取任务；图片挂接读当前任务后同步更新。轻量检查只将对应面板的评分合并到当前任务，不写回整个旧快照，并核对该面板图片和提示词没有改变。其他面板的图片、评分和用户编辑不会因此被覆盖。

异步 HTTP、Comfy 提交和图片保存返回后重新检查任务存在性，删除后的迟到结果不重新创建任务或 jobs。检查仅覆盖图片队列；脚本/深度复审等其他 runner 的删除竞态仍需独立审查。
