# 配置同步契约与恢复说明

## HTTP 契约

1. 读取 GET /api/config，保留响应 ETag。响应标记 no-store，版本取决于服务器完整记录而非浏览器时间。
2. 保存 PUT /api/config，发送 V2 配置 JSON 和 If-Match: <刚读取的 ETag>。
3. 只有 HTTP 成功、JSON success=true 且返回新 ETag 才可将草稿标记为服务器已保存。
4. 400：配置格式无效；428：缺少版本，先读取；412：版本变化，保留本地草稿并提示冲突。重试不自动覆盖新版本，也不使用通配符强制写入。
5. 多次快速修改串行发送，后续写入使用前一次确认的版本。网络失败保留草稿，不宣称已保存。

旧直接调用 PUT 的脚本必须改成先 GET 版本；旧数据迁移仅向空配置库写入。一般作品迁移不受这个配置版本契约替代。

## 浏览器恢复

- 当前标签页未同步内容写入 sessionStorage 的 comicpedia_api_config_tab_draft；模型密钥新输入不落盘，丢失输入时以标记要求重新输入。
- 兼容共享缓存为 localStorage 的 comicpedia_api_config；携带 _sync.revision / _sync.dirty，但这些元数据不发送给配置 API。
- 原始旧格式或无法解析的共享缓存第一次被替换前保存在 comicpedia_api_config_legacy_backup。后续写入会去除可解析模型列表中的 key；无法解析的历史原文仍可能包含秘密，不能贴到日志或分享。
- 刷新会优先读取本标签页草稿；若服务器版本不同则显示冲突。读取服务器版本需要用户确认，才替换当前草稿。
- sessionStorage 不是跨浏览器、跨设备或永久备份。关闭标签页后的草稿恢复不保证；处理冲突前保留所需内容。
- 配置导出已覆盖 LLM/VLM/文生图/检索配置与角色选择，默认排除 API 密钥和工作流；不能当作完整凭据备份。导入导出规则见 CONFIGURATION_TRANSFER.md。
