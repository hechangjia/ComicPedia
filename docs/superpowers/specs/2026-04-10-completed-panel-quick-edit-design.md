# 2026-04-10 完成态漫画单格速改设计

> Date: 2026-04-10
> Status: Draft for review
> Scope: 结果页完成态漫画编辑体验

## 目标

把已生成完成的漫画结果页编辑模式，从“整稿编辑器”改成“单格速改工作台”，让用户可以直接针对某一格修改：

- 对话
- 场景描述
- 图片提示词
- 单格图片重生成
- 保持提示词不变，仅换随机种子重生成

本设计的目标不是扩展整稿创作能力，而是让完成态作品的后期微调更直接、更符合结果页使用场景。

## 背景与问题陈述

当前结果页恢复了完成态漫画的 `编辑模式` 入口，但实际仍复用旧的 `ScriptEditor`。这个路径有三个明显问题：

1. 完成态作品的常见操作是“改一格、看一格、重新生成一格”，不是重新编辑整部脚本。
2. `ScriptEditor` 的核心优势在于整稿结构编辑，例如增删格、复制格、拖拽重排；这些能力对完成态结果页是噪音，而且容易让用户误以为要重新进入整稿工作流。
3. 仓库里已经存在更贴近目标的单格编辑能力：`PanelGrid + EditablePanel`，但它目前只在 `script_ready` 流程中自然可用，完成态没有真正走这条路径。

结果是：用户虽然看到了“编辑模式”，但体验仍然像在使用一个不适配完成态场景的工具。

## 范围

本设计覆盖：

- 完成态漫画结果页的编辑模式分流
- 单格默认展开编辑的结果页工作台
- 单格保存、单格重生成、单格换随机种子
- 完成态与 `script_ready` 的编辑边界
- 相关测试与回归验证

本设计不覆盖：

- 面板增删、复制、拖拽重排
- 重新生成整部漫画脚本
- 参考图编辑入口改造
- AI 导演、准确性研究、脚本校验、质量评分的功能定义调整
- 默认生成链路性能策略调整

## 用户决策结论

本次设计已经基于用户确认收敛到以下结论：

- 完成态漫画默认采用“单格速改”
- 编辑模式进入后，所有面板默认直接展开可编辑
- 不保留完成态的整稿结构编辑作为默认入口

因此，本设计明确把“完成态后期微调”和“脚本阶段整稿编辑”拆成两条不同路径。

## 核心设计

### 1. 结果页按任务状态分流编辑体验

结果页编辑模式不再统一落入 `ScriptEditor`，而是按任务状态分流：

- `script_ready`
  - 保持现状
  - 继续使用整稿编辑能力
  - 允许增删格、复制格、拖拽重排等结构操作
- `completed`
  - 改为结果页内的单格速改工作台
  - 每格直接展开编辑区
  - 只允许字段微调和单格图片重生成

这个分流保持了两个阶段的职责清晰：

- `script_ready` 负责“定结构”
- `completed` 负责“修成片”

### 2. 完成态编辑模式改走 `PanelGrid + EditablePanel`

不新造一套完成态编辑器，直接复用现有单格能力：

- 结果页完成态编辑模式渲染 `PanelGrid`
- `PanelGrid` 继续逐格挂载 `EditablePanel`
- `EditablePanel` 对完成态开放编辑权限
- `EditablePanel` 支持由父层传入“默认展开编辑态”

这样做的原因：

- 已有组件已经支持编辑 `scene`、`dialogue`、`imagePrompt`
- 已有组件已经支持 `保存`、`重新生成`、`随机种子重生成`
- 已有组件已接上单格更新与单格重生成的任务动作
- 改造集中在“权限和展示模式”，而不是重新开发业务链路

### 3. 完成态默认全部展开

进入完成态编辑模式后，不再先显示静态卡片再逐格点开。

行为定义：

- 所有格子默认处于展开编辑态
- 每格可直接看到：
  - 对话输入框
  - 场景描述输入框
  - 图片提示词输入框
  - 保存按钮
  - 重新生成按钮
  - 随机种子重生成按钮（已有图片时）
- 仍然保留图片预览、面板编号、版本切换、单张下载等已有结果页能力

选择“默认全部展开”的理由：

- 用户当前的主要诉求是“别再绕”
- 结果页的核心任务是快速修局部，而不是做分层工作台导航
- 对短中篇漫画，直接可见所有输入区比反复点开更省操作成本

### 4. 单格操作语义

完成态单格编辑只提供三类动作：

#### 保存

- 仅持久化当前格的 `scene`、`dialogue`、`imagePrompt`、`styleOverride`
- 不自动触发图片生成
- 不影响其他格

#### 重新生成

- 如果当前格处于编辑中，先保存当前字段
- 然后仅对当前格触发图片重生成
- 不重跑整部漫画链路
- 不影响其他格

#### 随机种子重生成

- 保持当前格提示词不变
- 只换随机种子以获取不同构图、姿态或细节
- 仍然只影响当前格

这个语义必须在完成态保持稳定，避免用户误以为点击某个按钮会重跑整部任务。

## 组件与文件落点

主要改动点如下：

- `src/app/result/[id]/page.tsx`
  - 调整结果页编辑模式分流
  - `completed + edit` 时不再进入 `ScriptEditor`
  - `script_ready + edit` 继续使用 `ScriptEditor`
- `src/components/result/PanelGrid.tsx`
  - 支持完成态编辑时向子面板传递“默认展开编辑态”
- `src/components/EditablePanel.tsx`
  - 允许 `completed` 状态进入编辑
  - 支持父层控制默认是否展开
  - 保持 `script_ready` 之外不开放结构编辑能力

不计划修改：

- `src/components/editor/ScriptEditor.tsx`
  - 该组件保留给整稿编辑阶段，不再承担完成态修图职责

## 数据流与状态约束

### 完成态编辑

1. 用户进入结果页并切换到 `编辑模式`
2. 结果页判断任务状态为 `completed`
3. 渲染 `PanelGrid`
4. `PanelGrid` 逐格渲染 `EditablePanel`
5. 每格默认展开输入区
6. 用户执行 `保存` 或 `重新生成`
7. 复用现有 `useTaskActions`：
   - `handlePanelUpdate`
   - `handleRegenerate`
   - `handleCancel`
   - `handleVersionChange`

### 权限边界

- `completed`
  - 允许字段微调
  - 允许单格图片重生成
  - 不允许结构编辑
- `script_ready`
  - 保留字段编辑
  - 保留结构编辑
  - 保留队列与批量生成工作流

这样可以避免完成态结果页变成第二个脚本工作台。

## 错误处理

本设计沿用现有任务动作错误处理，不新增复杂异常体系：

- 面板字段更新失败时，继续使用结果页瞬态错误提示
- 单格图片重生成失败时，继续显示第 N 格生成失败错误
- 单格取消生成继续沿用已有取消逻辑

额外要求：

- 完成态编辑失败不能把视图回退到整稿编辑器
- 完成态重新生成失败不能影响其他格已完成图片

## 测试与验证

至少覆盖以下验证：

### 自动化测试

- 结果页视图分流测试
  - `completed + edit` 使用完成态速改工作台
  - `script_ready + edit` 继续使用 `ScriptEditor`
- `EditablePanel` 权限测试
  - `completed` 可以编辑
  - `script_ready` 可以编辑
  - 仅 `script_ready` 保留结构编辑入口

### 集成验证

- 已完成漫画进入编辑模式后，所有面板默认展开
- 修改某一格的 `场景 / 对话 / 图片提示词` 后可以保存
- 修改后点击 `重新生成` 只重生成当前格
- 点击随机种子按钮只影响当前格
- 阅读模式和播放模式不回归

### 全量回归

- `pnpm lint`
- `pnpm test`
- `pnpm build`

## 风险与控制

### 风险 1：完成态编辑与 `script_ready` 编辑边界混淆

控制方式：

- 只在结果页分流层做职责区分
- 不把结构编辑能力塞进完成态工作台

### 风险 2：展开所有面板导致页面显得更长

控制方式：

- 这是用户明确选择的交互
- 当前优先级是减少点击成本，不是压缩页面高度

### 风险 3：误改最近做好的生成提速链路

控制方式：

- 本设计不修改脚本生成和研究链路
- 只调整结果页编辑渲染与已存在的单格动作复用

## 结论

本设计将完成态漫画编辑模式从“整稿编辑器复用”改为“结果页单格速改工作台”。

它解决的是一个明确的产品错配问题：用户在成片阶段需要的是逐格修正与逐格重生成，而不是重新进入整稿编排工具。通过复用 `PanelGrid + EditablePanel + useTaskActions`，可以用较小改动获得更符合直觉的完成态编辑体验，同时不回退近期已经完成的性能与治理修复。
